# ATHANOR Goal 006 — integration design and execution plan

## Inspected boundary

Goal 005 `Discovery._compile` fits constant coefficients, then installs one prescribed
input-plus-effect expression. It constructs operational knowledge but does not search
process structure. `Procedure`, typed endpoints/results, nested `call`, `if`, `fold`,
atomic transactions, pinned references and persisted receipts already support general
composition. The shared structural encoder/recurrent field/scorer accepts new native
structures without adding parameters. Grounded checkpoints own knowledge, activation,
optimizer and inquiry state. All of these contracts are retained.

## Process contract

A process consists of a native executable Procedure plus an inspectable native process
hypothesis. It records typed endpoints/results, the call expression, constituent pinned
operations, preconditions, observable output, applicability/evidence, alternatives and
revision history. Execution remains exact and bounded in the kernel. Learned applicability
is separate from an expression's mathematical validity. Installation is not mastery.

## Construction and selection

A general bounded constructor builds call trees from explicitly available compatible
operations, input slots, and taught constant participants. It does not receive an answer,
world object identity or private physics. It supports sequential/repeated invocation,
multiple inputs, and conditional/reduction operators when installed as compatible native
processes. Acquired processes enter the same library and can be composed again by reference.
Exact expression duplicates are removed; observational equality does not prove identity.

Candidate and interface proposals use the existing encoder and shared scorer, conditioned
by current recurrent activation. Evidence supplies measured discrepancy, coverage,
uncertainty, reliability and complexity features. Neural selection chooses proposals to
assess/adopt; contract/evidence gates can reject but cannot supply a replacement answer.
Shared training uses measured execution feedback with retention of established scores.
Search limits fail or leave unknown explicitly; exhaustion never proves absence.

## Evidence and correspondence

Restricted observations become attributed native transition records. Camera projections
exclude ambiguous identity, unavailable stereo, unmeasured rotation and stale images.
Independent numerical packets expose ordered/nested numeric fields through a distinct
interface. Candidate mappings enumerate typed selectors, not field-name meanings; the
shared model selects mappings based on observed preservation of input/output behavior.
Native adapter Procedures perform binding, then call the same acquired process. Unsupported
or conflicting correspondences remain unknown/qualified. Observed domains and measurement
tolerances are explicit; numerical execution can be exact while physical evidence is noisy.

Support requires repeated distinct inputs plus successful subsequent prediction checks.
Failed candidates and conflicting receipts remain visible. Invalidated support qualifies
dependent mappings/processes recursively. Capability evidence separates recognition,
binding, execution and transfer; existence alone increments none of those successes.

## Runtime, persistence and acceptance

The existing Runtime owns process inquiry alongside constant-effect discovery. Bounded
motor inquiry selects actual actions; each consequence feeds both learning paths. Viewer
and headless commands expose construction, candidate scores, mappings, adoption, execution,
capabilities and resources. Inspection is pure. Complete checkpoints add process metadata
while retaining outer formats 1–3 and exact native procedure/namespace protections.

World authority can install a native actuator or interaction law, kept entirely in world
knowledge. SensorFrame does not expose that law. The acceptance uses changing body
displacement magnitudes through limited proprioception. The observer seeds its history
from the first actual measurement because the initial private actuator state is unavailable.
It must infer a composition from permitted body consequences, reject alternatives,
predict fresh values,
learn a correspondence to structured numeric packets, then compose its acquired process
again. The same model, knowledge and optimizer continue from the 0.5 checkpoint.

7. Verify constructor breadth, atomic failures, scope, competing explanations, contradictions,

The user explicitly requested design followed by complete implementation in this workstream;
no additional design approval stage is introduced. No delegation is requested or used.
