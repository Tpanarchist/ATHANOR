# Concept formation and structural induction: Goal 007 contract

The inspected 0.6.0 system distinguishes exact native structures and revisions, binds
typed endpoints, executes portable Procedure expressions, grounds stereo/body feedback,
and ranks bounded quantity call trees with the shared recurrent encoder/scorer. Scalar
meaning, arithmetic, motor intentions, camera appearance descriptors and numeric leaf
selectors are predefined. Process evidence discovers applicable compositions, not new
structural concepts. A fitted value, selected procedure, composed procedure, discovered
relationship, operational concept, inferred transformation and goal solution are separate
achievements and receive separate evidence/capability records.

## One execution and learning architecture

Extend the cornerstone expression algebra with bounded structural sequence, relation,
graph and raster algorithms. These are precise generic functions, not whole problem
solutions. Records and sequences remain the common immutable values. Graph protocols
contain ordered node records and directed index pairs; rasters contain rectangular rows
of exact symbolic values with None as absence. Raw observations supply neither correct
groups nor roles. Connectivity, counting, ordering and geometry are exact computation.

The structural discovery front end uses the Goal 006 Candidate/native call representation
and a general typed unary composition constructor. All candidate, concept, adapter and
plan execution passes through Athanor.execute, including resource and transaction checks.
There is no generated source, external teacher, separate interpreter, task-family network
or authoritative environment reference inside the observer.

## Concepts and roles

Recurring field distinctions, equality/difference, frequency, relational participation
and pairwise ordered relations propose operational concepts without supplied names.
Membership is an executable predicate over typed item/index/root/peer roles. Missing
properties produce unknown; booleans never compare equal to numbers. Different identities
can occupy roles; directed links and ordered predicates preserve argument order.
Concepts are native records with procedures, observations, support, conditions and
revisions. Competing conceptual interpretations remain separate native participants. Concepts can use acquired concepts by reference. Recognition
does not assert that an observational partition is universally meaningful.

## Transformation and objective induction

Examples are attributed native before/after records. A bounded neural-ranked call grammar
constructs transformations from general operations and concepts. Predictions determine
error and contradictions; only consistent multi-example candidates can be supported.
The shared scorer learns from those discrepancies with the existing owned optimizer and
retention anchors. Neural order controls proposal budgets, candidate selection and tests;
evidence vetoes invalid choices. Multiple consistent explanations remain separate and a
query on which they disagree returns uncertainty. No hidden generator program is supplied.

Goals contain structural conditions, current state, operation scope and bounded resources.
Conditions compile into native predicates over an explicit initial/current frame.
Concept eligibility refers to the initial observation, preserving roles when current
relationships change. Cardinality can prevent an empty subset from satisfying a goal. Planning evaluates native transitions and
ranks partial solutions with the shared recurrent model. Exhausted search is unknown,
never impossibility. Successful sequences are variable-input native Procedures; one
success is provisional. Subsequent outcomes qualify or support reuse and generalization.

## Integration, evidence and preservation

GroundedObserver owns structural inquiry beside existing inquiry. Observations and active
concept/rule/task references participate in its recurrent graph. Capability history counts
concept recognition, relation application, rule construction, execution, goals, transfer
and generalization separately. Contradictions qualify dependent abstractions transitively
without deleting pinned history. Checkpoint format 5 retains native inquiry references,
tasks, capability history, model and optimizer; formats 1--4 stay readable.

Application commands and a problem editor accept exact structural observations, examples,
queries and goal constraints. Viewer state is read-only and exposes actual evidence,
alternatives, outcomes and learning. Headless input uses the identical Application path.

Acceptance restores the real 0.6 checkpoint and uses independent procedural relational
and raw raster situations, anonymous properties and unseen identities. Private generator
programs produce outputs only; observer code receives observations/examples and objectives.
It demonstrates unnamed concepts, competing rules, held-out inference, ambiguity,
multi-step goals, cross-interface concept reuse, larger composition and restart continuation.
No ARC data, published puzzles, solution material or benchmark optimization is permitted.

Implementation order: native structural algebra and contracts; common process constructor
and shared consolidation; concepts/examples/role binding; objectives and reusable plans;
checkpoint/runtime/application; independent continuous acceptance; preservation tests,
package and viewer verification. Initial limits are finite small structures and bounded
call composition, not unrestricted induction or a claim of general intelligence.

Shared checkpoint storage uses compact canonical JSON to retain every native revision
and receipt within the unchanged 256 MiB member import budget. Human-readable native
snapshots remain the default; either representation has the same semantic digest.
